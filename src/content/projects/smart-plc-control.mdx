## 🧠 Problem Statement

Industrial monitoring systems must bring equipment state, process values,
alarms, historical data, and operator permissions into one reliable view.
Developing against a physical PLC adds cost and safety constraints, while a
dashboard that is tightly coupled to one protocol is difficult to test or
extend.

**SmartPLCControl** is a wastewater-focused monitoring and simulation platform
that models a plant before physical PLC integration is required. It provides a
guided setup workflow for plants, process units, devices, tags, alert rules, and
simulation scenarios. Operators can then monitor simulated process data in real
time, reproduce fault conditions, and exercise alert workflows in a safe
environment.

The application separates a **React and TanStack Start client** from a **Go and
Gin API server**. REST endpoints provide initial state and configuration, while
WebSockets broadcast incremental simulation and tag-reading updates. PostgreSQL
stores plants, process units, devices, tags, historical readings, alert rules,
alerts, simulations, scenarios, users, and audit logs through GORM models.

The backend is divided into feature modules with handlers, services,
repositories, and DTOs for `plants`, `process_units`, `devices`, `tags`,
`tag_readings`, `alert_rules`, `alerts`, `simulations`, `simulation_scenarios`,
`users`, and `audit_logs`. Authentication uses JWTs, and role middleware
enforces permissions for administrators, operators, and viewers on the server
rather than relying on hidden frontend controls.

### 🧭 Guided Plant Configuration

The client includes a multi-step plant setup wizard for plant information,
users, process units, process connections, devices, tags, alert rules, and
simulations. A process arrangement board stores unit positions and port-to-port
connections, making the configured facility easier to understand than a set of
unrelated database forms.

### 📡 Simulation and Real-Time Monitoring

The simulator produces the same normalized tag concepts expected from future
Modbus TCP or OPC UA adapters. WebSocket events can announce updated readings,
device state changes, alerts, and simulation lifecycle transitions. Keeping the
client behind the API ensures it never communicates directly with a physical
controller.

### 🌐 Accessible Operations

The UI includes English and Traditional Chinese resources, persistent language
selection, responsive navigation, tables, charts, and role-aware routes. This
supports both operational use and demonstration in a Taiwanese industrial
context.

The schema models both the physical hierarchy and its operational history.
Plants contain process units and devices; devices expose tags; tags produce
time-stamped readings and feed alert rules. Simulation scenarios reuse the same
plant model, and audit logs record important user and system actions.

## 🚀 Key Features

- JWT authentication with `ADMIN`, `OPERATOR`, and `VIEWER` roles
- Guided plant, process-unit, device, tag, alert, and simulation setup
- Visual process-unit arrangement with stored connections and positions
- PLC tag definitions and historical reading storage
- Configurable threshold operators, severities, and alert lifecycle states
- Start, pause, stop, and fault-scenario simulation workflows
- Real-time WebSocket broadcasting for simulation events and process readings
- Audit logging for important configuration and control actions
- English and Traditional Chinese localization
- Adapter-ready design for future Modbus TCP and OPC UA integrations

## 🧩 Challenges & Learnings

Industrial data must be treated as untrusted input even when it originates from
plant equipment. This project emphasizes server-enforced authorization,
normalized tag values, data-quality states, auditability, and a hard boundary
between browser clients and PLC communication. Building the simulator first also
makes alert rules and real-time UI behavior testable without connecting to
production equipment.

> **Safety note:** SmartPLCControl is intended for monitoring, simulation,
> learning, and demonstration. It should not control production or
> safety-critical equipment without engineering review, fail-safe design,
> network security, operational testing, and applicable compliance work.
